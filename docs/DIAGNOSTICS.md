# 診断ログ仕様 v1

## 基本動作

ログは初期状態 OFF、レベルは `warn` です。OFF の通常記録処理はディレクトリの作成・追記・回転をしません。設定画面で有効化、レベル、ファイルサイズ、世代数、保存先を変更できます。ZIP 生成はユーザーの明示操作だけで行い、ネットワーク送信機能を持ちません。

既定の保存先は専用ブラウザプロファイル内の `privacybrowser-diagnostics` です。保存先の変更は絶対パスのみを受け付けます。POSIX ではディレクトリ `0700`、ファイル `0600` を設定します。Windows の ACL に同じ隔離性を保証する実装・実機検証は未完了です。

| 項目 | 既定値・範囲 |
| --- | --- |
| 形式 | UTF-8 JSON Lines、1 行 1 レコード |
| レベル | `debug`, `info`, `warn`, `error`。設定画面は error／warn／debug |
| 1 ファイルの上限 | 1 MiB。API の許容範囲は 1 KiB〜100 MiB |
| 総ファイル数 | 3（現行ファイルを含む）、範囲 1〜20 |
| ファイル名 | `diagnostics.jsonl`、`diagnostics.1.jsonl` 等 |
| 書込み待ち行数 | 最大 256。超過分は捨て、件数のみ保持 |
| リソース採取 | 有効時のみ 5 秒間隔。タスク表示と同じ Gecko API。実行環境によって利用不能・非代表値になるため、メモリ目標への適合判定には通常環境での再計測が必要 |

追記は直列化し、次の行が上限を超える前に回転します。無効化や明示削除後に、既に待機中のレコードが再び書き込まれないよう世代番号で取り消します。ログ I/O エラーでブラウザ本体を停止させず、失敗件数を保持します。

## 許可するデータ

```json
{"version":1,"timestamp":"2026-10-19T00:00:00.000Z","level":"debug","event":"resource-sample","data":{"pid":1234,"cpuPercent":3.5,"residentBytes":104857600}}
```

| 種類 | 許可フィールド |
| --- | --- |
| 有限・非負の数値 | `pid`, `tabId`, `extensionIndex`, `cpuPercent`, `residentBytes`, `privateBytes`, `durationMs`, `processCount`, `tabCount`, `failedCategoryCount`, `exitCode`, `errorCount` |
| 真偽値 | `cleanExit`, `recovered`, `forced`, `succeeded` |
| 固定コード | `unknown`, `network`, `signature`, `permission`, `conflict`, `unavailable`, `io`, `api`, `cleanup` |

自由文、例外メッセージ、スタックトレース、URL、検索語、Cookie、パスワード、フォーム内容、拡張 ID、タブタイトル、パス、オブジェクトの任意の子要素は許可しません。アクセサープロパティや継承プロパティも読み取りません。診断の観測対象へ検索通知の本文を渡しません。

## イベントと接続範囲

| イベント | 現在の接続・制限 |
| --- | --- |
| `startup`, `shutdown` | BrowserGlue の起動／正常終了。初期の warn 設定では info 行を記録しない |
| `resource-sample` | 診断有効時のプロセス CPU／RAM を debug で採取。プロセス総量でありタブ別ではない |
| `crash` | コンテンツプロセスの異常終了通知を固定コードで記録。親プロセス自身のクラッシュでは最終書込みを保証しない |
| `internal-exception` | 連携コードの失敗やスクリプトエラーを本文なしで記録。現時点で第三者のページエラーと内部エラーの厳密な分類は未完成 |
| `tab-terminated` | スキーマは対応。すべての終了経路への接続・実機検証は未完成 |
| `update-failure` | スキーマは対応。未展開の製品更新サービスとの接続は未実装 |
| `extension-error` | スキーマは対応。拡張ごとの安全な分類・接続は未完成 |
| `privacy-cleanup-failure` | スキーマは対応。全失敗経路の個別分類・接続検証は残る |

「スキーマで受け付ける」ことを、そのイベントが全経路から実際に記録されるという意味にはしていません。実 Gecko の API から ZIP の生成・上限・削除・検索語の非混入を確認しています。全イベント接続とファイル選択を含む実画面確認は、通常コンテンツが動作する Windows／Linux 環境で続ける必要があります。

## ZIP 診断パッケージ

設定画面の **Export diagnostic ZIP…** で出力先を選びます。内部 API も `userInitiated:true` を必須とし、それ以外を拒否します。記録を OFF にしたままでも、既存ログを明示的に削除・出力できます。

ZIP に含むものは次の 2 ファイルだけです。

- `manifest.json`：スキーマ、製品名、診断専用フラグ、レコード数、I/O エラー数、捨てたレコード数。
- `diagnostics.jsonl`：保存済みログをもう一度ホワイトリストで検査したレコード。

読み取る世代数・サイズを上限内に制限し、不正 JSON、長過ぎる行、不正な時刻・イベント・レベルを除外します。プロファイル一式、設定ファイル、raw stderr、クラッシュダンプを含めません。一時ファイルへ生成してから出力先へ移動し、失敗時の一時ファイルを削除します。自動アップロードはありません。

## 検証と保証範囲

`tests/unit/diagnostics-core.test.mjs` と `privacy-gecko.test.mjs` は無効時 I/O ゼロ、許可フィールド、Unicode、回転、競合、無効化、削除、ZIP 要求の明示性、再サニタイズ、I/O 失敗を検証します。Linux 統合試験では実 Gecko による ZIP 生成・サイズ上限・削除・秘密文字列の除外も確認しました。これらと、両 OS におけるファイル選択の実画面操作・ACL・全終了経路・クラッシュ時の実証は区別します。診断ログ以外の OS／ESR の生ログや外部サービスの記録はこのスキーマによる保護範囲外です。
