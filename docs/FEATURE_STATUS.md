# 機能実装・検証の状況

対象：Privacy Browser v0.1.0-dev、ESR 固定値 `153.5.1esr`。初期開発実装であり、全機能完成・正式配布可能という状態ではありません。実装が存在することと、実際の OS／Gecko で成功を確認したことを分けて記載しています。

注意：既存のランタイム・UI の実測結果は ESR 153.5.0 に対する履歴です。153.5.1 の検証範囲と未完了ゲートは [更新記録](ESR_153_5_1_UPDATE.md) を参照してください。

## ネイティブ Linux テストの読み方

`tests/results/linux-integration.json` が実際の起動テストの根拠です。最新の保存結果は **20 項目成功、1 項目保留** です。

| 確認対象 | 実際に確認した範囲 |
| --- | --- |
| 起動と UI | 親／chrome 起動、独自ボタン、URL キーワード検索無効、全保存フラグ OFF、ホームの system principal とモジュール実行、設定の 8 チェックボックス |
| タスク画面 | 実 Gecko の行表示、選択された対象タブ、内部行の終了ボタン無効化 |
| 保存制御 | Unicode 検索語の opt-in 保存と削除、テスト Cookie 削除、ブックマーク保持、正常終了後も SQLite 上のブックマークを保持 |
| 診断 | 初期 OFF、明示 API からの ZIP 生成、サイズ上限、削除、ZIP へのテスト検索語の非混入 |
| 終了後 | 親プロセスの終了コード 0、試験プロファイルにセッション／検索履歴／診断ファイルなし |
| 保留 | Brave 検索結果表示。外部検索の遷移を試行したが、結果ページ描画を実証できず `blocked` |

これは一時的な試験プロファイルに対する API と chrome の確認であり、全 Web サイト／各保存分類の再起動／クラッシュ・全プロセス終了の総合保証ではありません。`smoke_resources` は `representativeOfNormalBrowsing:false` で、起動 300MB 以下や 1GB RAM 目標の測定結果として使用できません。

同環境では user namespace 作成の `EPERM` とネイティブコンテンツクラッシュも検出しています。`sandbox_disabled:false`、`sandboxLevel:6` を維持し、この制約を解消するために保護を弱めてはいません。親／chrome の検査に成功しても、Web コンテンツが通常閲覧できた証拠にはなりません。初回には `SessionFileInternal.getWriter() called too early` を検出しました。閲覧削除をセッション全削除を伴わない `PlacesUtils.history.clear()` に変更し、最終再試験のネイティブ例外要約が空であることを確認しました。ソース側セッション保存ガードの独立ビルド検証は残ります。

Node の検査にある 6 キーワードは、検索 URL と Unicode エンコードのロジック試験です。Brave Search の検索結果表示や日本語 IME を操作した結果ではありません。Windows の自動テストは CI 設定の存在をもって実行済みとは扱いません。

## 優先する残作業

1. user namespace と通常コンテンツプロセスが利用できる Linux／Windows ホストを用意し、独立ブランドの ESR ソースをビルド。ネイティブ API とセッションガードを実証する。
2. Cookie とサイトストレージの実行中／クラッシュ時の非永続化方式を仕上げ、保存 ON/OFF 全分類・ブックマーク・実ダウンロードを再起動で検証する。
3. URL 入力、6 語の Brave 検索、日本語 IME、描画・タブ・戻る進む・タスク画面・フリーズ終了・最終ウィンドウ終了・子プロセス残留を両 OS で実測する。
4. Windows インストーラー、独立 Linux DEB、導入／削除、1GB RAM、CPU／全プロセス RAM、長時間リークを検査する。
5. GitHub に `PrivacyBrowser` を配置して CI を実行。独立署名鍵・証明書、Windows 更新／APT／ロールバックを展開し、正式公開検査を追加する。

`tools/release_gate.py` は現状の正式リリースを必ず拒否します。JSON のフラグやファイル名を変更するだけでは公開条件を満たせません。秘密鍵・証明書の秘密情報はソースへ入れません。
